# Story 2.2: Commit Data Preprocessing & Labeling

## Status
Draft

## Story
**As a** data engineer,
**I want** 커밋 데이터를 전처리하고 라벨링하는 시스템,
**so that** 검색 정밀도를 높일 수 있는 구조화된 데이터를 생성할 수 있습니다.

## Acceptance Criteria
1. 규칙 기반 1차 필터링으로 버전업/수정 관련 커밋을 선별합니다.
2. Azure OpenAI GPT-4o를 활용한 2차 LLM 분류가 구현되어 있습니다.
3. 패키지명, 버전, 에러타입, API 시그니처가 정형 필드로 추출됩니다.
4. JSON 형태로 구조화된 데이터가 생성됩니다.
5. 전처리 과정의 품질 검증 메커니즘이 구현되어 있습니다.

### Technical Constraints
[Source: docs/prd.md#technical-assumptions]
- **Preprocessing**: 하이브리드 규칙 + LLM 방식
- **LLM Service**: Azure OpenAI GPT-4o
- **Data Format**: JSON 구조화
- **Quality Validation**: 자동 검증 시스템

### Data Preprocessing Architecture
[Source: docs/prd.md#technical-assumptions]
```
Preprocessing Pipeline:
├── Input: Raw Commit Data
├── Stage 1: Rule-based Filtering
│   ├── Version Update Keywords
│   ├── Fix/Patch Keywords
│   └── Error-related Keywords
├── Stage 2: LLM Classification
│   ├── Azure OpenAI GPT-4o
│   ├── Classification Prompts
│   └── Quality Validation
├── Stage 3: Structured Field Extraction
│   ├── Package Name
│   ├── Version Info
│   ├── Error Type
│   └── API Signature
└── Output: Structured JSON Data
```

### File Locations
- 전처리 서비스: `data-ingestion/src/preprocessing/`
- LLM 통합: `data-ingestion/src/llm/`
- 데이터 모델: `data-ingestion/src/models/`
- 품질 검증: `data-ingestion/src/validation/`

### Data Schema
[Source: docs/prd.md#functional-requirements]
```json
{
  "commit_id": "string",
  "repository": "string",
  "branch": "string",
  "message": "string",
  "diff": "string",
  "author": "string",
  "date": "datetime",
  "classification": {
    "type": "version_update|fix|patch|error",
    "confidence": "float",
    "package_name": "string",
    "version": "string",
    "error_type": "string",
    "api_signature": "string"
  },
  "metadata": {
    "processed_at": "datetime",
    "quality_score": "float",
    "validation_status": "string"
  }
}
```

## Testing

### Testing Standards
- **Unit Testing**: 각 전처리 단계별 테스트
- **Integration Testing**: LLM API 연동 테스트
- **Data Quality Testing**: 구조화된 데이터 품질 검증
- **Performance Testing**: 대용량 데이터 처리 테스트

### Specific Testing Requirements for This Story
- 규칙 기반 필터링이 올바르게 작동하는지 확인
- LLM 분류가 정확하게 수행되는지 확인
- 정형 필드 추출이 올바르게 작동하는지 확인
- JSON 구조화 데이터가 올바르게 생성되는지 확인
- 품질 검증 메커니즘이 올바르게 작동하는지 확인
