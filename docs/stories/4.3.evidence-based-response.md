# Story 4.3: Evidence-Based Response Formatting

## Status
Draft

## Story
**As a** AI engineer,
**I want** 근거와 함께 응답을 포맷팅하는 시스템,
**so that** 사용자가 제안의 신뢰성을 평가할 수 있습니다.

## Acceptance Criteria
1. 참조된 커밋과 Diff가 명시적으로 표시됩니다.
2. 신뢰도 점수가 계산되어 제공됩니다.
3. 응답 형식이 일관되고 읽기 쉽게 구성됩니다.
4. 마크다운 형태로 포맷팅됩니다.
5. 응답 품질 메트릭이 측정됩니다.

### Evidence-Based Response Architecture
[Source: docs/prd.md#technical-assumptions]
```
Evidence-Based Response System:
├── Evidence Collection:
│   ├── Commit References
│   ├── Diff Content
│   └── Metadata
├── Confidence Calculation:
│   ├── Multi-factor Scoring
│   ├── Weight Normalization
│   └── Explanation Generation
├── Response Formatting:
│   ├── Template Engine
│   ├── Markdown Conversion
│   └── Style Consistency
└── Quality Metrics:
    ├── Response Quality
    ├── User Satisfaction
    └── Improvement Tracking
```

### File Locations

- 마크다운 엔진: `llm-service/src/markdown/`
- 품질 측정: `llm-service/src/quality/`

### Response Data Structure
[Source: docs/prd.md#functional-requirements]
```typescript
interface EvidenceBasedResponse {
  id: string;
  content: {
    summary: string;
    solution: string;
    codePatch?: CodePatch;
    explanation: string;
  };
  evidence: {
    commits: CommitReference[];
    diffs: DiffContent[];
    confidence: number;
    reasoning: string;
  };
  formatting: {
    markdown: string;
    sections: ResponseSection[];
    style: ResponseStyle;
  };
  quality: {
    metrics: QualityMetrics;
    timestamp: Date;
    version: string;
  };
}
```
