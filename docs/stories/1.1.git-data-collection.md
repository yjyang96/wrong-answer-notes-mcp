# Story 1.1: Git Commit Data Collection Service

## Status
Completed

## Story
**As a** data engineer,
**I want** Git 커밋 메시지와 Diff를 자동으로 수집하는 서비스,
**so that** 오답노트 데이터베이스의 원시 데이터를 확보할 수 있습니다.

## Acceptance Criteria
1. GitHub REST/GraphQL API를 통한 커밋 데이터 수집이 구현되어 있습니다.
2. git CLI를 통한 로컬 저장소 데이터 수집이 지원됩니다.
3. PyDriller를 활용한 커밋 메시지와 Diff 추출이 구현되어 있습니다.
4. 모든 브랜치의 커밋 데이터를 수집할 수 있습니다.
5. 수집된 데이터의 메타데이터(저장소, 브랜치, 날짜 등)가 보존됩니다.

### Technical Constraints
[Source: docs/prd.md#technical-assumptions]
- **Data Collection**: GitHub REST/GraphQL API, git CLI, PyDriller
- **Language**: Python (PyDriller) + TypeScript/Node.js (API 클라이언트)
- **Storage**: 임시 저장소 (후속 Story에서 벡터 DB로 이동)
- **Authentication**: GitHub Personal Access Token
- **Rate Limiting**: GitHub API 레이트 리미팅 준수

### Data Collection Architecture
[Source: docs/prd.md#technical-assumptions]

### Data Schema Requirements
[Source: docs/prd.md#functional-requirements]
- **FR1**: GitHub 저장소의 커밋 메시지와 Diff를 자동으로 수집하고 전처리할 수 있어야 합니다.
- **Commit Data**: 메시지, Diff, 작성자, 날짜, 해시
- **Repository Data**: 이름, URL, 브랜치 목록
- **Metadata**: 수집 시간, 소스, 버전 정보

### Integration Points
- **GitHub API**: 커밋 데이터 수집
- **Git CLI**: 로컬 저장소 분석
- **PyDriller**: 고급 Git 분석
- **Azure Key Vault**: API 토큰 관리
- **Application Insights**: 수집 모니터링

### Security Requirements
[Source: docs/prd.md#technical-assumptions]
- **API Authentication**: GitHub Personal Access Token
- **Rate Limiting**: GitHub API 제한 준수
- **Data Privacy**: 내부 데이터 사용 시 보안 고려
- **Access Control**: 최소 권한 원칙 적용

### Performance Requirements
[Source: docs/prd.md#technical-assumptions]
- **Collection Speed**: 대용량 저장소 처리 최적화
- **Memory Usage**: 효율적인 메모리 사용
- **Error Recovery**: 네트워크 오류 시 재시도 메커니즘
- **Batch Processing**: 배치 단위 데이터 처리
